# learning.md — Session-derived rules

Short, evolving guidance that Claude reads before answering, updated at session end. It's distinct from `CLAUDE.md` (rules by design) and `log.md` (event history): this file holds **rules learned from experience**.

**Cap:** ~50 active entries. When it's full, the next addition requires consolidating two entries, promoting one into `CLAUDE.md`, or dropping a stale one.

**Entry format:** `- [YYYY-MM-DD] <terse rule> — <why or origin>`. One line each.

**Promotion ladder:**
1. New rules start here.
2. An entry that survives about 3 sessions unchanged becomes a candidate for `CLAUDE.md`.
3. When an entry is promoted or contradicted, move it to **Recently struck** with a reason.

**End-of-session ritual:** Claude proposes 0–3 candidates, each as `+ <rule> — <why>`, and you approve them one by one. Zero is a common answer.
